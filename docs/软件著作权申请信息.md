## 四、开发目的

志愿服务活动的组织与开展长期依赖线下沟通，志愿者组织难以统一管理活动申报与志愿者报名，
志愿者也难以了解活动信息与自身参与情况。开发本软件的目的在于：

1. 为志愿者组织提供志愿活动线上申报、活动分类管理、报名人员管理与报名审核的完整工具；
2. 为平台管理部门提供志愿活动的统一审核入口，把控活动的合规性与可执行性；
3. 为公众提供志愿活动与志愿者组织的展示窗口，并支持志愿者线上注册；
4. 形成志愿活动从申报、审核到报名、开展、签到与服务时长核算的全流程数据记录，为志愿服务管理提供数据基础；
5. 以现场签到码、签到时间窗口、地理围栏与志愿者组织复核共同约束服务时长，解决服务时长真实性难核验的问题；
6. 按技能、距离、时间与历史参与为志愿者推荐合适的志愿活动，并为志愿者生成可在线校验的志愿服务证明。

## 五、面向领域 / 行业

志愿服务管理、社会公益与社区服务信息化领域，适用于志愿者协会、公益服务中心、社区服务机构、
学校青年志愿者组织等开展志愿服务管理工作的单位。

## 七、技术特点

1. **分层架构**：采用 Spring Boot 整合 Spring MVC、Spring Security 与 MyBatis-Plus，
   按控制器层、业务层、数据访问层、实体层分层设计，业务接口与实现分离，职责清晰、便于扩展。
2. **角色权限控制**：基于 Spring Security 实现统一的登录认证与基于角色的访问控制，
   页面资源与接口资源均按角色授权，未登录访问自动跳转登录页，越权访问返回 403。
3. **存储过程实现关键业务**：志愿者注册、志愿活动申报、志愿活动审核、活动重新申报、报名与候补、
   志愿者签到签退、服务时长复核、活动结算等涉及多表写库或需要行锁校验的业务通过 MySQL 存储过程实现，
   业务规则集中在数据库端执行，保证数据一致性与并发安全（如报名与审核时的名额校验使用行锁）。
4. **逻辑删除**：志愿活动、志愿者组织、报名记录、培训与公告等业务数据采用逻辑删除标记，
   删除操作只修改删除标记而不物理删除数据，保证历史数据可追溯。
5. **可信服务时长**：服务时长由现场签到码、签到时间窗口、地理围栏与志愿者组织复核共同约束，
   签到位置与时长异常的记录自动标记并进入人工复核，复核通过后才计入累计服务时长；
   线下服务由志愿者组织补录、平台管理员复核，录入与复核相互分离。
6. **供需匹配算法**：按技能命中比例、球面距离（MySQL `ST_Distance_Sphere`）、时间冲突与组织历史参与
   四个维度计算 0 至 100 的匹配度，打分为纯函数实现并配有单元测试。
7. **定时任务**：按活动时间自动流转活动状态，并释放活动开始前仍未确认参加的报名名额，两个任务均为幂等批量操作。
8. **统一分页与导出**：列表接口统一分页参数与响应结构，数据导出按 RFC 4180 生成带 UTF-8 字节序标记的 CSV。
9. **文件存储**：附件与图片按随机存储名保存，限制白名单扩展名与单文件大小，下载按存储名校验，避免目录穿越。
10. **密码安全**：登录密码采用 PBKDF2WithHmacSHA256 加盐摘要保存与校验，比对时使用恒定时间比较，
    历史 MD5 摘要密文在账号登录成功后自动升级为加盐密文；系统不保存、也不在日志中输出密码明文。
11. **证明防伪**：志愿服务证明的校验码由平台密钥对志愿者累计服务数据计算 HMAC-SHA256 摘要得到，
    数据变动后校验码同步变化，第三方可在线核验证明真伪。
12. **操作审计**：活动审核与流转、报名审核与移除、服务时长复核与补录复核、活动结算、账号启停、密码重置与修改、
    公告发布与删除、志愿秀删除等关键操作写入操作审计表，可按操作类型与操作账号查询。
13. **数据模型完整**：数据模型覆盖志愿者、志愿者技能、志愿者组织、平台管理员、统一用户、志愿活动、
    活动技能、活动报名、志愿服务记录、志愿培训、志愿者培训情况、志愿活动公告、通知公告、公告附件、
    志愿秀、志愿秀图片、志愿秀点赞、站内通知与操作审计等业务对象。
14. **开箱可用**：项目提供完整的数据库脚本（建库、建表、存储过程与初始化数据）与可直接运行的构建产物，
    执行数据库脚本并启动程序即可使用，并提供初始化管理员、志愿者组织与志愿者账号。
